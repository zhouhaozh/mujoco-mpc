# 环境安装与部署

本文档说明如何在一台新机器上安装项目依赖、编译仿真程序并运行
MuJoCo 仿真。日常策略、参数和评测命令见 [操作手册](../USAGE.md)。

## 1. 支持范围

已验证的基线环境为：

- Ubuntu 24.04 x86_64。
- Python 3.12。
- MuJoCo 3.14.0、CasADi 3.8.0 和 NumPy 2.5.4。
- `requirements-sim.txt` 中锁定的其他仿真依赖。

一键安装脚本只接受 Ubuntu 24.04 x86_64，其他 Ubuntu 版本、Windows、macOS
和 ARM 会直接退出。项目包含 Linux x86_64 专用的预编译库，不能直接用于其他
系统或架构。

安装前建议准备：

- 可访问 Ubuntu 软件源和 Python 包索引的网络。
- 至少 5 GiB 可用磁盘空间和 4 GiB 内存；这是为下载与编译预留的建议余量，
  不是最低配置保证。内存紧张时使用 `--jobs 1`。
- 可在安装 `apt` 包时使用 `sudo` 的账户。脚本只在安装缺失的系统包时
  调用 `sudo`；虚拟环境、Python 包和编译产物均位于项目目录。

## 2. 新机器一键安装

GitHub 仓库可通过公开 HTTPS 地址克隆，无需配置 SSH key。如果系统尚未安装
Git，先执行：

```bash
sudo apt update
sudo apt install -y git
```

克隆并安装：

```bash
git clone https://github.com/zhouhaozh/mujoco-mpc.git
cd mujoco-mpc
bash tools/install_ubuntu.sh
```

脚本根据自身位置确定项目根目录，因此也可以从任意目录用绝对路径调用：

```bash
PROJECT_DIR=/absolute/path/to/mujoco-mpc
bash "$PROJECT_DIR/tools/install_ubuntu.sh"
```

不要用 `sudo` 运行整个脚本。否则 `.venv`、`deps` 和编译目录可能归
root 所有，导致后续增量编译失败。

### 可选参数

```text
bash tools/install_ubuntu.sh [--skip-system-deps] [--jobs N] [--index-url URL] [--help]
```

| 参数 | 用途 |
| --- | --- |
| `--skip-system-deps` | 不检查和安装 `apt` 包。仅用于已准备好编译器、CMake 和图形系统库的环境。 |
| `--jobs N` | 指定并行编译任务数，默认为 `2`。低内存机器建议使用 `--jobs 1`。 |
| `--index-url URL` | 指定 Python 包索引。镜像必须包含 `requirements-sim.txt` 锁定的全部版本，否则安装会失败。 |
| `--help` | 显示帮助信息后退出。 |

`--skip-system-deps` 不会帮助判断现有环境是否完整。使用此选项前，应已安装
`python3`、`python3-venv`、`build-essential`、`gcc-13`、`g++-13`、`cmake`、
`libeigen3-dev`、`nlohmann-json3-dev`、`libglfw3` 和 `libgl1-mesa-dev`。

例如，在已安装系统依赖的低内存机器上使用指定镜像：

```bash
bash tools/install_ubuntu.sh \
  --skip-system-deps \
  --jobs 1 \
  --index-url https://pypi.org/simple
```

## 3. 脚本做了什么

脚本依次执行以下阶段：

1. 检查 Ubuntu 和 x86_64 架构。
2. 检查系统依赖，并通过 `apt` 安装缺失项。已安装的包不会重复安装。
3. 在下载 Python 包前检查 `sckd_sim/third_party/osqp/libosqp.a` 的 SHA-256，
   并确认 C/C++ 编译器、CMake 和 CTest 可用。
4. 创建项目专用 `.venv`，按 `requirements-sim.txt` 安装锁定的 11 个
   Python 包，然后运行 `pip check`。
5. 在 `deps/` 中建立 MuJoCo 和 CasADi 头文件与库的项目内链接；
   仅在缺少 `sckd_sim/third_party/nmpc6/nlp.so` 时从源码补编译。
6. 将 CMake 工程配置、编译到 `sckd_sim/build`。
7. 运行 10 项 CTest。
8. 在无图形窗口模式下运行 3 球 `pfly` 冒烟仿真。

脚本不会自动打开 GUI。脚本以退出码 `0` 结束、10 项 CTest 全部通过且
3 球 `pfly` 冒烟仿真完成，表示基础安装、编译和无头仿真链已跑通。任一阶段失败
时脚本会以非零状态退出；应先处理第一个错误，再重新运行脚本。

## 4. 安装后运行

### 无头仿真

服务器、CI 或没有图形桌面时，不要设置 `M2_VIEW`：

```bash
cd sckd_sim
./build/m2_intercept models/generated/x4_tennis_demo.mjcf 3 qp 0.25 2026 pfly
```

仿真程序的退出码 `1` 不一定表示崩溃：`m2_intercept` 在运行完成但命中率未达
评测门槛时也会返回 `1`。先查看末尾的 `命中 N/M` 汇总和错误输出；动态库
加载失败、段错误或资源文件缺失才属于运行故障。

### 本机 GUI

在图形桌面会话中确认 `DISPLAY` 已设置，再从项目根目录启动：

```bash
echo "$DISPLAY"
tools/run_mujoco_demo.sh
# 可选：指定策略和球数
tools/run_mujoco_demo.sh nmpc6 3
```

脚本启动 viewer 和仿真进程，默认使用 `pfly` 策略运行 3 球。如需分开
控制 viewer 和仿真进程，见 [GUI 操作说明](../USAGE.md#3-gui-可视化看仿真效果)。

### SSH 远程 GUI

优先使用无头仿真。必须远程显示时，需要客户端 X server、SSH X11 转发和
服务端允许 X11 转发，例如：

```bash
ssh -X user@server
echo "$DISPLAY"
cd /absolute/path/to/mujoco-mpc
tools/run_mujoco_demo.sh
```

某些环境需要 `ssh -Y`。远程 OpenGL 是否可用取决于客户端、SSH 服务器和显卡驱动，
不是本项目的安装脚本能够保证的。`DISPLAY` 为空时不要启动 GUI。

### 可选录像

GUI 录像使用系统 `ffmpeg`，不是基础安装和无头仿真的必需项：

```bash
sudo apt install -y ffmpeg
```

录像命令见 [操作手册](../USAGE.md#3-gui-可视化看仿真效果)。

## 5. 更新、重跑与换机

依赖中断、源码更新或编译失败后，可从项目根目录重新执行：

```bash
bash tools/install_ubuntu.sh
```

脚本会复用项目内的 `.venv`、`deps` 和 CMake 构建目录，并再次执行测试与
冒烟仿真。如果只需增量编译和测试：

```bash
cmake --build sckd_sim/build -j2
ctest --test-dir sckd_sim/build --output-on-failure
```

换机时只克隆或复制源码仓库，然后在新机器重新运行安装脚本。不要复制
旧机器的 `.venv/`、`deps/`、`sckd_sim/build/`、旧软链接或包缓存；这些内容
包含绝对路径或与本机 Python/ABI 绑定的文件。

## 6. 仓库中必须保留和不应提交的内容

以下 Linux x86_64 二进制是当前仿真的运行依赖，不要删除：

- `sckd_sim/third_party/osqp/libosqp.a`
- `sckd_sim/third_party/nmpc6/nlp.so`

保留 `sckd_sim/third_party/osqp/LICENSE` 以及其他第三方许可证和归属说明。
不要用来源不明的二进制覆盖仓库内已校验的 OSQP 库。

以下是本地生成内容，不应提交到 GitHub：

- `.venv/`、`.venv-*/`、`venv/`。
- `deps/`。
- `sckd_sim/build/`、`sckd_sim/build-predictor/` 及其他 `build*` 目录。
- Python/CMake 缓存、中间文件和本地软链接。
- 日志、录像、临时评测报告、认证信息和本机编辑器状态。

`.gitignore` 已覆盖上述主要路径，并显式保留两个必需二进制。提交前可检查：

```bash
git status --short --ignored
git check-ignore -v .venv deps sckd_sim/build
git ls-files sckd_sim/third_party/osqp/libosqp.a \
  sckd_sim/third_party/nmpc6/nlp.so \
  sckd_sim/third_party/osqp/LICENSE
```

已纳入历史的算法记录、评测结论和许可证不应因为清理本地产物而被删除。

## 7. 不在一键安装范围内的功能

一键脚本只部署默认仿真、内置预测链、CTest 和 `pfly` 冒烟验收。以下内容
需要额外资源或独立环境，不由脚本自动准备：

- 外部 GP/MLP 模型、权重和实测数据。
- 额外的预测器训练或评估环境。
- 真机设备、驱动和通信配置。
- GUI 录像所需的可选 `ffmpeg`。

`tools/setup_predictor_ubuntu.py` 作为原有 Python 安装后端继续保留；默认构建目录仍为
`sckd_sim/build-predictor`。它支持 `--build-dir`、`--jobs`、`--index-url` 和为旧团队
归档保留的 `--archive`。新机器常规部署应优先使用 `install_ubuntu.sh`。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 缺少 Git | 执行 `sudo apt update && sudo apt install -y git`，再通过 HTTPS 克隆。 |
| `apt` 或 `sudo` 权限失败 | 使用具有系统包安装权限的账户，或请管理员预装依赖后使用 `--skip-system-deps`。不要用 `sudo` 运行整个脚本。 |
| 提示资源、MJCF、URDF 或 STL 缺失 | 确认使用完整 Git 克隆，且没有仅复制部分子目录。用 `git status` 检查误删文件。 |
| OSQP 缺失或哈希不匹配 | 使用仓库中原始 `libosqp.a`，不要从旧机器或其他架构复制。原有后端可通过 `--archive /path/to/original-team-archive.tar.xz` 恢复缺失库，但仍会校验固定 SHA-256。 |
| Python 包版本找不到 | 去掉自定义 `--index-url`，或确认镜像已同步 `requirements-sim.txt` 中的所有固定版本。不要用未锁定版本替换。 |
| 提示动态库找不到 | 可执行 `ldd sckd_sim/build/m2_intercept`，查找输出中的 `not found`。重跑安装脚本只会补齐缺失的 `deps` 链接；如果提示 `refusing to replace`，说明目标位置已有异常文件或指向其他机器的旧链接。确认它们是本机生成的旧 `deps` 链接后，移除相应链接并重跑安装；不要复制旧机器的 `deps/`。 |
| GUI 报 `DISPLAY is not set`、黑屏或无法创建窗口 | 在本机图形会话或配置好的 SSH X11 转发会话中运行。没有显示环境时使用无头仿真。 |
| `m2_intercept` 返回 `1` | 检查是否已打印完整的 `命中 N/M` 汇总。完整运行后未达命中率门槛与崩溃不同；若出现段错误、动态库或资源错误，再按运行故障处理。 |

需要更细的策略选择、GUI 双进程用法和评测门槛时，继续阅读
[操作手册](../USAGE.md) 和 [`sckd_sim` 说明](../sckd_sim/README.md)。

## 9. 安装入口验证记录

2026-10-27，在 Ubuntu 24.04 x86_64 / Python 3.12 上完成以下验证：

- 将源码复制到一个路径含空格、没有 `.venv`、`deps` 或构建产物的独立目录。
- 从目录外执行 `install_ubuntu.sh --skip-system-deps --jobs 4`，固定依赖安装、
  完整构建、10 项 CTest 和三球 `pfly` 仿真均通过，命中 3/3。
- 再次执行安装入口，验证环境和构建目录可重复使用；即使父环境设置了
  `M2_VIEW`，安装验收也不会开启视图状态写入。
- 11 项安装回归测试通过，覆盖路径含空格、参数传递、帮助无副作用、
  系统包提权边界、失败中止、架构拒绝和 OSQP 下载前校验。
- `apt-get --simulate install` 验证了系统依赖包能够解析；当前验证环境禁止
  sudo，实际系统包安装阶段使用隔离替身测试覆盖，未执行真实提权安装。

这些结果证明了当前环境下的安装和默认仿真链；未验证其他操作系统或新机器的
SSH 图形转发与显卡驱动。
