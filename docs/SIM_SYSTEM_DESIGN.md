版本 v1.1(2026-10-05)。本文从需求出发全新设计,不继承既有工程架构;既有工程仅作为硬件事实来源与经验参考(见 §13)。

## 1. 需求分解与量化指标

### 1.1 原始需求 → 派生需求

| 编号 | 原始需求 | 派生需求(设计必须满足) |
|---|---|---|
| R1 | 仿真器推荐 MuJoCo,不强制 | 引擎需同时满足:轮-地持续滚动接触稳定、球-拍毫秒级冲击可标定、CPU 单环境 ≥10k steps/s、GPU 可并行 ≥1000 环境(RL)、确定性可回归、URDF 导入 |
| R2 | 舵轮全向底盘 + 单臂;有电机手册、实机接口、URDF | 仿真中**执行器接口与实机同构**(混合控制律、限幅、延迟、量化、使能/看门狗语义);URDF→MJCF 可审计管线;模型参数分级(理想/手册/随机/辨识) |
| R3 | 仿真 MPC/RL/Odom;底盘与臂末端高动态精确控制 | 控制栈分层且 sim/real 同一套代码;内环 ≥500Hz、物理 ≥1kHz;延迟与感知噪声从第一天就注入;末端(拍心)跟踪与时序精度可度量 |
| R4 | 末端球拍,网球/羽毛球对打(网球先行) | 球飞行动力学(气动分级)、拍-球接触按回弹行为标定、来球生成器、回合状态机与计分、命中点/挥拍规划、四层指标体系 |

### 1.2 关键时序推导(决定频率指标的物理依据)

以网球来球为例(业余对打典型值):来球速度 10~25 m/s,拦截点距击球位 3~8 m → 可用决策+移动+挥拍时间 **0.2~0.8 s**。

延迟链叠加:

```
相机曝光+传输 5~15 ms → 轨迹预测收敛 30~80 ms(需若干帧观测)
→ 拦截规划 5~20 ms → 命令链路延迟 ~9 ms(实测值) → 机电响应 50~200 ms
```

命中窗口:甜区有效范围约 ±0.05 m,挥拍相对速度 8~20 m/s → **拍-球时间同步误差预算 ≈ 3~6 ms**,拍心位置误差预算 ≈ 4~6 cm。羽毛球(后续变体)更严:甜区更小、挥拍相对速度更高,预算回收至 2~5 ms。

由此得出硬指标:

| 指标 | 目标值 |
|---|---|
| 物理步长 | 默认 1 ms,接触校核场景 0.5 ms |
| 伺服内环(轮 PI/舵环/臂混合控制) | 500~1000 Hz |
| MPC 求解频率 | ≥200 Hz(单次求解 <2 ms) |
| 拦截/挥拍重规划 | ≥50 Hz |
| 感知仿真帧率 | 100~200 Hz,延迟 10~20 ms 可配 |
| 仿真吞吐(in-process) | 单环境 ≥10k steps/s(CPU),RL ≥1024 并行环境 |

## 2. 总体架构

### 2.1 核心设计决策(D1~D13)

| # | 决策 | 理由 |
|---|---|---|
| D1 | **MuJoCo 单引擎双后端**:CPU `mujoco` 精细仿真 + GPU `MJX` 并行 RL,共用同一 MJCF | R1 全部条件满足(论证见 §3.1);单模型来源避免双引擎漂移 |
| D2 | **一套控制栈、双运行形态**:in-process(算法研究/RL/批量实验)与 sim-service(实时性验证/HMI/未来实机)通过同一 HAL 接口 | RL 需要进程内高速率;实时性验证需要进程隔离 + 墙钟;实机部署形态天然是分离进程 |
| D3 | **执行器保真优先于物理保真**:电机命令律、T-N 降额、延迟、量化、看门狗逐项对齐手册与实测;接触参数以"行为标定"(回弹比、滑移率)为目标 | sim2real 失败主因是接口与非理想性缺失,而非求解器精度 |
| D4 | **信息流即实机**(no-privileged-info):延迟与感知噪声在接口层注入;算法层只允许访问与实机同构的观测(调试白盒模式可配置开启) | 否则仿真指标无法外推,RL 学会利用真值作弊 |
| D5 | **分层规控**:回合任务 → 拦截规划 → 整机 MPC(级联起步、整机 OCP 为目标形态)→ 伺服分配 → 电机 | 各层频率、失效模式、可替换性不同;MPC 与 RL 可在同一层级 A/B 对比 |
| D6 | **RL 定位为高层决策 + 残差补偿**,端到端仅作对照 | 样本效率、安全性、可解释性;高层(命中点选择)是感知噪声下真正的策略问题 |
| D7 | **球模型分级 T0~T2**,规划/RL 用 T1,验收评估用 T2;拍-球接触按回弹行为标定 | 网球阻力+马格努斯使轨迹显著偏离抛物线、旋转主导反弹方向,必须显式建模;接触按行为而非材料参数标定 |
| D8 | **保真度分级 F0~F3**(理想/手册/随机化/辨识),同一代码路径切换参数集 | 支撑课程学习、DR、标定迭代,避免多套代码 |
| D9 | **评测驱动开发**:每里程碑定量验收;固定种子确定性回归进 CI | "平均达标"不等于通过;沿用时序超时/跳过的严格口径 |
| D10 | **网球先行,羽毛球复用**(已确认):球/场地/回合抽象(`BallSpec`/`CourtSpec`)+ 机器人变体(`RobotVariant`:末端拍惯量 + 个别关节电机差异) | 两拍差异 = 气动/反弹/场地 + 末端惯量与电机差异,全部为配置差异而非代码分支;网球拍末端参数待输入(§14)(§8.1) |
| D11 | **算法核心 C++17**:估计/规划/控制/RL 推理为 C++17 模块,in-process 直连 MuJoCo C API;Python 仅限训练与离线工具 | 真机移植零重写;实时形态天然同构;推理无框架依赖(§4.3) |
| D12 | **控制层接口算法中立**:`IWholeBodyController` 下基线/MPC/MPPI/RL/残差可运行时切换 | "哪种算法最优"由统一评测协议回答,而非架构预设(§6.4) |
| D13 | **感知层三源统一**:`IBallObservationSource` 下 仿真观测 / 真机日志观测回放 / 影子球轨迹回放 可运行时切换 | 真机数据从第一天进入算法与评测回路:噪声校准、预测器离线评测、真实来球分布下的闭环击打(§3.6) |

### 2.2 分层视图

```
┌─────────────────────────────────────────────────────────────────┐
│ L5 任务层    回合状态机 · 来球生成 · 计分 · 指标采集              │ 5~20 Hz
├─────────────────────────────────────────────────────────────────┤
│ L4 规划层    球轨迹估计/预测 · 命中点选择 · 挥拍轨迹生成          │ 20~100 Hz
│             · 底盘预击球位姿与局部轨迹                            │
├─────────────────────────────────────────────────────────────────┤
│ L3 控制层    [A] 整机 MPC(acados/CasADi)                        │ 200~500 Hz
│             [B] RL 策略(高层命中参数 / 残差)  ←与 A 同层可换      │
├─────────────────────────────────────────────────────────────────┤
│ L2 伺服层    舵轮分配 IK · 轮速 PI · 臂混合控制+重力前馈          │ 500~1000 Hz
├─────────────────────────────────────────────────────────────────┤
│ L1 机器人抽象层 (HAL)   RobotInterface:命令/状态/延迟/噪声注入    │
│        ├─ SimBackend(in-process:直连 MuJoCo)                     │
│        ├─ ServiceBackend(共享内存⇄sim-service)                   │
│        └─ RealBackend(未来:实机 robotd/CAN)                      │
├─────────────────────────────────────────────────────────────────┤
│ L0 物理层    MuJoCo/MJX:机器人+球+场地 · 执行器模型 · 气动 ·      │
│             接触参数 · 感知仿真 · 确定性 RNG                      │ 0.5~1 ms
└─────────────────────────────────────────────────────────────────┘
横切:可视化/日志/回放 · 标定工具 · 回归评测 CI · 配置与种子管理
```

### 2.3 进程拓扑

**形态一 in-process(默认,研究与 RL)**:控制器模块与物理引擎同进程,物理全速推进。延迟与噪声仍由 HAL 在**信息流层面**注入(内部队列),不依赖墙钟等待——保真的是因果结构,不是耗时。

**形态二 sim-service(实时性验证与 HMI)**:独立仿真服务按墙钟推进物理;控制器(建议 C++)经**无锁共享内存双缓冲**(状态帧/命令帧各一带序列号的环形区)交互,RTT 降至微秒级;TCP/HTTP 仅用于工具与面板等非实时通道。选共享内存的依据:既有实测显示 TCP 吞吐足够(~13k RPC/s)但**尾延迟与调度抖动**是瓶颈;闭环 500~1000 Hz 的诚实测量需要更短路径。

两形态共享 L1 接口与全部上层代码。

## 3. 仿真内核与物理建模

### 3.1 引擎选型论证(满足 R1"推荐但可替换")

| 候选 | 轮-地接触 | 球-拍冲击 | CPU 吞吐 | GPU 并行 | 确定性 | URDF | 结论 |
|---|---|---|---|---|---|---|---|
| **MuJoCo 3.x + MJX** | 凸优化软接触,8 轮持续接触稳定 | solref/solimp 可标定回弹 | 本模型 ~30 DOF,≥10k steps/s | MJX 数千环境 | 同种子逐位一致 | 官方导入 | **主线** |
| Isaac Lab(PhysX) | 滚动摩擦粗糙 | 偏稳定不偏复现 | 高 | 极高 | 可 | 可 | 不进主线;如 RL 需更大规模再评估 |
| PyBullet | 一般 | 调参受限 | 低 | 无 | 可 | 可 | 否 |
| Drake | 强(多体/优化) | 接触生态弱 | 中 | 无 | 可 | 可 | 作为 MPC 建模辅助库备选,不做引擎 |

MuJoCo 冲击场景要点:默认 `solref` 时间常数(0.02 s)远大于冲击时长,必须收紧至 `timeconst ≈ 2~4×dt`、`dampratio ≈ 1`,摩擦用椭圆锥并调 `impratio`;标定目标见 §3.5。

### 3.2 机器人模型管线

```
source/X4_5/*.urdf + STL ──build──▶ robot.mjcf ──merge──▶ scene.mjcf
                                        │                    │
                   执行器/电机手册参数 ──┘          + 球 + 场地 + 发球器 + 相机标记
```

- 转换为**显式构建步骤**,输出"变更清单"(provenance manifest):惯量是否保留、碰撞体如何替换、关节限位来源——每项可审计、可复现。
- 审计已知问题(继承自硬件事实,非架构包袱):源连杆惯量未经整机辨识;B/d4 几何定义有矛盾;拍碰撞代理是近似盒/柱,需替换为**拍面平面 + 框边胶囊**组合;连续关节的线缆行程未确认,仿真限位保守取值并显式标注。
- 惯量/质量参数集中在一个 `model_params.yaml`,与 MJCF 生成解耦,F0~F3 分级在此切换。

### 3.3 执行器保真(R2 的核心)

每个关节一个"电机模型"组件,逐项对齐手册与实测:

| 项目 | 建模 | 来源 |
|---|---|---|
| 控制律 | `τ_req = Kp(q_d−q) + Kd(dq_d−dq) + τ_ff` | RS04 手册 p43 / RS06 p41 |
| 限幅链 | `min(机构限矩, 峰值/连续档, T-N 包络(速度,方向))` | 手册曲线(现有为读图估值,`calibrated=false`) |
| T-N 降额 | 分段线性包络,推动方向按 `τ·dq>0` 判定,制动独立上限 | 手册 p8(待实测替换) |
| 命令延迟 | 默认 9 ms,可配 | 实测 |
| 命令/反馈速率 | 1 kHz | 实机协议 |
| 反馈量化 | 编码器分辨率(默认 14 bit,可配)+ 偏置 | 待实机确认 |
| 语义 | 使能/失能零输出但物理继续;看门狗断流锁存;模式仅失能时可改 | 实机接口 |
| 关键限矩 | **按变体**:羽毛球机 J5=RS05,有效上限 5.5 N·m(URDF,手册待补);网球机 J5=RS06(峰值 36/连续 11 N·m;URDF 无机构限矩标签,暂按电机包络并显式标注该假设);J1/J2 120(RS04),J3/J4 36(RS06) N·m | URDF+手册+用户指示 |
| 可选高保真(F3) | 转子附加惯量、库仑+粘滞摩擦、i²t 热降额、背隙 | P2 升级项 |

物理引擎内不实现控制律——**电机模型在 L0 作为 MuJoCo 执行器的外壳函数**先算 `τ_req` 再写 `ctrl`,物理只受力矩。这与实机"控制器在电机侧"的结构一致。

**手册原件归档(`docs/motors/`,2026-10-05):** RS04/RS06 PDF+TXT 齐备(RS04 原件经 gh-proxy 自 RobStride 公开仓库补全,62 页);关键规格已逐项核验与既有参数化一致(RS04:120/40 N·m、200 rpm、9:1、±15 rad/s;RS06:36/11 N·m、480 rpm、9:1、±50 rad/s;Kp 0~5000/Kd 0~100 同)。新录得电流/热建模备用参数:转矩常数 RS04 2.1、RS06 1.09 N·m/Arms;反电势 RS04 16.9、RS06 7.6 Vrms/krpm。RS05 手册待羽毛球变体启用时补(§14-7)。

### 3.4 轮-地与舵轮运动学

- 8 驱动轮 + 4 舵(每组双轮同轴、左右镜像轴)。轮半径 0.0825 m,角间距方形布置(corner 0.475 m)。
- 轮胎:椭圆摩擦锥,滑动摩擦 μ∈[0.8, 1.2](F3 辨识);低速原地转舵的双轮刮擦力矩显式出现在接触中——这是双轮舵轮特有的能耗/滑移源,列为标定实验之一。
- 舵轮分配(L2 伺服):`(vx,vy,ω) → 4×(舵角θᵢ, 双轮速ωᵢ)`;采用实机验证过的协同策略(参考工程 ADR-0009):**最近角语义 + >90° 迟滞反转(反转体现在轮速符号)+ 舵角误差 cos 投影降速(死区+下限)+ 速度死区保持当前舵角**;双轮差速 `v_j = v_corner − d_j·(ω + θ̇)`(d_j=±双轮半间距,j=0 在 +n 侧)——ω 与 θ̇ 统一处理。
- **舵轮控制模式(2026-10-05 决定,同日修正)**:实机 mpc6.0 舵轮为 CSP 位置模式、轮为固件速度环;本仿真采用**三层等价架构**——①物理层不变:17 轴全部混合律电机模型(力矩进物理,"固件仿真器"单一实现);②算法命令接口为**语义命令**(底盘=舵角/轮速目标,与实机命令域对齐;臂=混合命令/τ_ff);③伺服层(舵位置 PD、轮速 PI)为**我们代码里的显式环路**,走混合律通道,1 kHz。**MPC 所见被控对象 = 闭环等效模型**(舵:一阶滞后 T_steer + 9 ms 延迟,阶跃辨识;轮:加速度限幅 ≈8 m/s²)——实机无论 CSP/速度/混合模式,只要响应整定相近,MPC 模型不变;MPC 不直接优化舵轮力矩(避免与轮胎刮擦耦合)。
- **增益迁移策略(2026-10-05)**:仿真收敛的**环路增益不直接上真机**——armature=0 使实机转子反射惯量缺失数倍~数十倍(离散稳定界 kd<2I/dt 随之缩放,J5 已实证),且环路闭合位置/延迟/胎面负载不同。可整体迁移:控制律**结构**(PD+速率前馈+加速度前馈+抗饱和+停稳吸附)、整定**方法论**(阶跃辨识/稳定界/验收场景)、**模型项前馈**(重力=同源模型文件;加速度=m/8·a·r,CAD 质量);仿真增益仅作**保守初值**(实机惯量更大→更稳),上机按同一套阶跃场景做**行为对齐**(63% 时间/超调/稳态误差),实机辨识值回写仿真 F3,数据流方向为"实机标定→仿真"(steer_kp=12 即源自实机台架)。

### 3.5 球与空气动力(R4)

**分级模型(同一接口,`BallSpec` 切换):**

| 级 | 网球(先行) | 羽毛球(后续变体) | 用途 |
|---|---|---|---|
| T0 | 无阻力弹道 | 无阻力弹道 | 单元测试/解析校核 |
| T1 | 刚体+阻力 Cd≈0.55 + 马格努斯(Cl 随 spin 比),质量 ~57 g | 刚体+轴向二次阻力(姿态锁定速度方向),CdA≈0.0016~0.002 m²(终端速度 ≈6.8 m/s 反推),质量 ~5 g | 规划、RL、控制器内模型 |

### 4.3 算法模块化与真机移植(C++17 核心)

算法核心(估计/规划/控制/RL 推理/回合逻辑)全部为 **C++17** 模块;Python 只保留 RL 训练与离线工具。in-process 形态下算法直接链接 MuJoCo C API——**同一份二进制在仿真与实机运行**(仅 HAL 后端不同)。

**模块接口(纯虚 + 依赖注入,禁止全局状态):**

```cpp
// 估计

                                                  const RobotState&) = 0; };
```

**移植规则(强制,CI 检查):**

1. 算法模块内**禁止**包含仿真器头文件(MuJoCo/MJX)——只依赖 `core/` 类型与 HAL 接口;仿真知识只允许存在于 HAL 后端。这是"仿真代码不上真机"的结构化保证。
2. 模块间只传 POD 消息结构,单位/坐标系按 §4.2 契约,类型定义唯一来源 `core/types.h`。
3. 每个模块边界可开关地记录输入/输出日志 → 离线回放做单元测试(录制输入 → 断言输出);真机采集的数据可反向灌入仿真调参。
4. 参数全部配置注入(无编译期魔法数);同一二进制按配置切换 F0~F3、RobotVariant、算法实现。
5. 对 Python 侧仅暴露薄 C ABI;pybind11 包装为独立包,不部署到实机。
6. RL 推理:训练在 Python/JAX,产物 = 扁平权重文件 + 归一化表,C++17 Eigen 前向(策略为小 MLP,不依赖 ONNX/PyTorch 运行时)。

### 5.2 IMU(已确认后续提供)——收益清单与接入

| # | 收益 | 作用机理 |
|---|---|---|
| 1 | 免滑移、高带宽的车体角速度/比力 | 陀螺直接给出 `wz`;轮速解算值受滑移与量化污染。直接改善内环反馈质量,作用于 §1.2 的 2~5 ms 时序预算 |
| 2 | 底盘俯仰/横滚可观测 | 挥拍反力矩与加减速打破"底盘纯平面"假设;世界系拍位/拍面 = 底盘姿态 ⊕ 关节——无 IMU 时拍面法向误差不可观 |
| 3 | 滑移检测与里程计门控 | IMU 比力 vs 轮速差分的残差 = 滑移指示 → ESKF 动态加权;击球高机动段恰是轮里程计最差的段 |

| 5 | 延迟优势 | IMU 为毫秒级延迟;轮速经 PI 闭环存在等效滞后 |
| 6 | 事件信号 | 加速度计高频段含挥拍反力矩轮廓,可机会性检测**真实拍-球冲击时刻**(实测 `t_hit` vs 计划 `t*`,闭合时序校准回路);若后续提供腕部第二 IMU,该检测近乎确定可用 |
| 7 | 辅助监测 | 轮地打滑颤振、结构异常诊断信号 |

**期望管理:** IMU 不提供绝对位置;主要收益在**速度/姿态质量与滑移鲁棒性**——恰好命中本任务"高机动段精度"的痛点。

**指标:** 每米平移漂移、速度 RMSE(对真值,评估器可见)、**有/无 IMU 对照表**;高机动段与静止段分段统计——高机动击球段的里程计退化是本任务特有的问题,单列指标。

## 6. 规划与控制(R3+R4)

### 6.1 全栈

```
球观测流 ─▶ 轨迹估计/预测(EKF + T1 气动外推, 输出预测球道+协方差)
      └─▶ 命中点选择:在预测球道上采样候选 (p*, t*),评分=可达性+时间裕度+回球意图
      └─▶ 击球参数求解:目标落点→反解所需拍速 v* 与拍面法向 n*(T1 反弹模型)
      └─▶ 挥拍轨迹生成:末端(拍心+拍面)轨迹,终端约束=在 t* 经 p* 且速度 v*、法向 n*
      └─▶ 底盘轨迹:p* 映射"预击球位姿"(臂工作空间优选区),限加速度局部轨迹
             ↓
整机控制器(算法中立接口:基线/MPC/MPPI/RL,§6.4) @200~500 Hz → 关节速度/力矩前馈目标
             ↓
伺服层 @500~1000 Hz:舵轮分配 + 轮速 PI + 臂混合控制 + 重力前馈(模型计算,经限幅)
             ↓
HAL → 电机模型(延迟/限幅/降额) → MuJoCo
```

### 6.2 MPC 两种方案(级联起步,整机为目标形态)

**方案 A(M2 起步,级联;底盘块 M1b 先行):**
- 底盘:运动学 MPC(或动态标定下的轨迹跟踪),状态 `(x,y,θ,vx,vy,wz)`,输入加速度。
- **约束(2026-10-05 修正:摩擦圆而非轴独立方框)**:加/减速与速度均为**矢量模约束** `‖(ax,ay)‖≤a_max`、`‖(vx,vy)‖≤v_max`——QP 以 M=8 内接正多边形线性化(`cosθk·ax+sinθk·ay ≤ a_max·cos(π/M)`,保守侧);a_max=8 m/s² = min(μg=9.8, 轮力矩链)×0.8 工程裕度(实机标定同值;高速段 T-N 降额可能绑,F3 后细化);角加速度 20 rad/s²、wz 1.57、舵角变化率等效(方向角率 3 rad/s)独立限。严格"每轮力多边形"(转向刮擦占摩擦预算)留 M2 细化。
- **航向窗口约束(2026-10-05,依实机感知构型)**:旧版 MPC 无航向是因底线相机+二维码定位的可见性约束(朝向偏大即丢定位);本方案**保留 θ 于状态**,以软约束表达可见窗 `|θ−θ_qr|≤θ_max` + 越界时长/代价限制(IMU+里程计桥接,典型 ≤2 s)——常规走位锁窗内(与旧版等效),击球窗口允许短暂越界换取挥拍动量(旧版做不到),回正后 QR 重锚。不采用旧版"删除航向"的结构性规避。
- 臂:任务空间/关节空间 MPC,模型为臂动力学(含基座运动耦合的视加速度),约束 = 关节限位/限速/T-N 力矩包络(J5 5.5 N·m 尤其关键),目标 = 拍心位置+拍面法向跟踪挥拍轨迹。
- 优点:两块小 OCP,求解快、调试易;缺点:底盘-臂动力学耦合只在规划层近似。

**方案 B(M3+,整机 OCP):**
- 单一模型:底盘视作平面单刚体(输入 = 轮系可实现的平面力/力矩,受摩擦椭圆约束)+ 5 轴臂完整动力学;状态 ≈ 16 维 + 力矩 17 维输入。
- 终端约束直接表达命中任务:`racket_pos(t*) = p*, racket_vel(t*) = v*, racket_normal(t*) = n*`——击球即带终端流形的 OCP,与挥拍轨迹生成合一。
- 求解器:**CasADi 原型 → acados(SQP-RTI)**,单次 <2 ms 目标;求解失败/超时必须显式上报并回退到上一可行解(禁止静默)。

**基线对照(必需,兼作 RL 教师):** IK+PVT 轨迹跟踪控制器——简单、可解释,作为 MPC/RL 的下限基准与模仿学习数据源。

### 6.3 资格约束的现实(设计必须内化)

5 轴臂 + 底盘平面 3 自由度 = **8 控制自由度**;拍任务 = 位置 3 + 法向 2 + 命中时刻速度 3 ≈ 8 维——**无冗余或近无冗余**。网球机腕部:J4(轴 z)+ J5(绕拍杆滚转 = 拍面开合角,§3.2.1);羽毛球机为 J5 俯仰——按变体加载,不混用。腕部权威按变体:羽毛球机 J5=RS05 限 5.5 N·m × 0.915 m 拍杆,极紧;网球机 J5=RS06(峰值 36 N·m)驱动 0.417 kg 拍(横惯量 ~0.019 kg·m²)充裕,约束焦点移至 J2/J3(RS04 承 0.705 m 上臂+拍)与各轴速度上限。挥拍必须是**鞭打式动量传递**(J1~J3+底盘储能,腕只精修拍面),MPC 力矩约束与挥拍轨迹优化必须联合处理;这也是残差 RL 的重点作用点。

### 6.4 "MPC 是否最优?"——算法中立接口与候选矩阵

直接回答:**MPC 不是全局最优,但对"挥拍段"是当前最合适的骨架;感知噪声下的决策与模型误差补偿,RL 类方法更优。** 本系统不押注单一算法:控制层接口算法中立(§4.3 `IWholeBodyController`),各实现可运行时切换,优劣由统一评测协议回答。

| 候选 | 优势 | 弱点 | 本系统角色 |
|---|---|---|---|
| IK+PVT 基线 | 简单、可解释、零模型依赖 | 无约束意识、无时序最优 | 下限基准 + RL 教师数据源 |
| 级联 MPC(方案A) | 约束显式、求解快、易调 | 底盘-臂耦合仅近似 | M2 起步骨架 |
| 整机 OCP(方案B) | 约束+终端命中流形+时序最优 | 建模与求解难度高 | 目标形态 |
| MPPI(采样式 MPC) | 无梯度、对接触/随机动力学友好;可与 MJX 复用 GPU rollout | 算力大、方差需调 | 挥拍段强候选(接触+限矩病态时) |
| 高层 RL(E1) | 感知噪声下选点是真正的策略问题 | 约束/安全是软的 | 命中点决策层 |
| 残差 RL(E2) | 补模型误差/延迟,保留基座约束保证 | 需基座稳定 | 叠加于 MPC/基线之上 |
| 学习残差动力学 + MPC | 提升内模型精度(标定+仿真数据) | 数据依赖 | F3 之后增强项 |

### 6.5 击球意图的执行分解(2026-10-05,依实机接口事实)

**拍速的来源**:指令给出球速度 V_out(spd/yaw/pitch/speed_z)而非拍速;拍速 v* 与拍面法向 n* 由
反弹模型逆解导出(固定 n 扫描,取拍速最小/落在力矩包络内的 (v*,n*))——即臂 NLP 终端流形
为四元组 (P_hit, v*, n*, t*)。

**底盘/臂分解(级联方案 A)**:
- 拦截规划:球道采样候选 (P_hit,t*),逐个试分解,不可行换点(可行性级联的入口);
- 底盘:目标 = 预击球位姿 (x_b,y_b,ψ_b) + 到达时刻 t*−t_swing,**t* 时底盘速度≈0**
  (v1 拍速全由臂出;升级:底盘沿挥拍方向供能)。位姿由离线**可达性/灵巧度图**
  (击球点×法向需求×底盘位姿的 IK 可行性)在线查取——底盘位姿的使命是让 (P_hit,n*)
  对 5 轴臂可达且有余量,ψ_b 定挥拍平面朝向;
- 臂 NLP:终端流形 (P_hit,v*,n*,t*),J5 力矩包络进约束。

**执行到位三重保证**:①可行性级联回退(IK 失败→换点;臂 NLP 力矩/时间不够→降 v* 或提前 t*;
底盘不可达→换点),逐层显式上报;②滚动重规划窗口策略:t*−t_prep 前 P_hit 随球预测 50Hz 滚动,
**挥拍窗口开启后冻结大改、仅 ±2cm/±10ms 微调**(挥拍中途大改必失稳);③量化验收(拍心 RMSE/
甜区偏移/时序误差,§8.2)。演示版(1a07165)即无 v*/n* 闭环的反例:开放式拍面致出球高飞 44m。

**MPC 与 RL 的兼容模式(接口已预留,均为组合而非二选一):**

1. **残差叠加**:action = MPC 输出 + 限幅后策略残差;
2. **教师预热**:MPC 滚筒生成示教 → 模仿学习 → RL 微调;
3. **安全回退(simplex)**:策略失稳/超界 → 基线控制器接管并显式上报;
4. **学习模型进 MPC**:辨识/神经网络残差进入 OCP 动力学。

**评测协议:** 同一 1000 发球种子集 + 四层指标(§8.2),基线/MPC/MPPI/RL/混合并列报告;算法切换是配置项而非代码分支。

### 7.2 训练

- 算法:**SAC**(E1/E2,样本效率)主;**PPO**(MJX 大规模并行,E2/E3)。
- 并行:CPU 多进程 64~256 环境(精细 MuJoCo)或 MJX 于单卡 1024~8192 环境(本机 RTX 5090 适配;RL 模型用基元碰撞代理,与 MJX 能力对齐)。
- 课程:固定发球器参数 → 参数域随机 → 全域随机来球 → 回合对打;E1 内嵌"预测协方差越大越保守"的隐式压力。
- DR(D8):电机 Kp/Kd 缩放、摩擦、延迟 0~20 ms、气动系数 ±20%、感知噪声域、地面 μ。
- 评估协议:固定 1000 次随机发球种子集(与训练种子隔离),合法回球过网入场率为主指标;报告分位而非均值。
- 推理移植:训练产物 = 扁平权重 + 归一化表,C++17 Eigen 前向(§4.3),真机零框架依赖。
- 变体条件化:DR 域包含 RobotVariant 参数(拍惯量、电机差异)→ 可训练单一变体条件策略,或每变体独立策略(对照实验)。

## 9. 保真度分级与 Sim2Real 标定计划(D7/D8)

| 级 | 定义 | 用途 |
|---|---|---|
| F0 理想 | 刚体、无限矩、无延迟 | 算法原型、RL 课程第 0 级 |
| F1 手册 | 电机限幅/T-N(现估值)、延迟 9 ms、量化、名义摩擦 | 默认开发级 |
| F2 随机 | F1 + DR 域(§7.2) | RL 训练、鲁棒性评估 |
| F3 辨识 | 实测参数逐项替换 | 上实机前门槛 |

**标定实验(每个有明确验收产物,按依赖排序):**

1. 臂动力学:各关节重力/惯量(静态多姿态力矩 + 小幅正弦辨识)→ 替换连杆惯量,静差复测。
2. 电机 T-N 与延迟:受控阶跃(不同转速下可用力矩)→ 替换读图包络。
3. 轮地:直线加减速与原地转舵的滑移/刮擦 → 摩擦参数 + 里程计噪声模型。
4. 球气动:真实抛射/击球高速摄像 → 拟合 Cd/Cl(网球,先行)、CdA(羽毛球,变体)。
5. 拍回弹:不同速度、拍面位置的回弹比 → 接触参数标定。
6. 感知通道:真机日志回放(§3.6 源②)统计 vs 仿真观测(源①)统计对齐——帧率、延迟、σ-距离曲线、丢帧率 → 校准源①噪声模型,纳入 F3。
