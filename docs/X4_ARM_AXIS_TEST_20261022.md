## 程序与边界

可执行文件为 `x4_arm_axis_test`。默认 `inspect` 只解析并检查配置，不构造设备服务。`sim` 使用 `ArmServerSim`；`hardware` 使用同一 SDK 内的 `ArmServer`，只接触机械臂 can4–6，不创建整机 `Robot`、底盘、IMU 或手柄服务，不执行 CAN 初始化脚本。

| 功能 | 当前行为 |
|---|---|
| 逐轴操作 | 界面使用 J1–J5，每条 `+`／`-` 只改变所选轴，其他目标固定 |
| 轨迹 | 默认单步 ±10°，五阶平滑，峰值速度 1°/s，单步 18.75 s；相对本轮初始目标保护 ±12°，第二次同向走到20°被拒绝；`--step-deg 1` 恢复旧1°/±3°模式 |
| 初始化目标 | 沿用 SDK 已发送的 home；不把重力下垂后的反馈重新当作目标 |
| 继续动作条件 | 五轴误差≤0.25°、速度≤0.5°/s，逐轴新反馈连续覆盖 0.25 s |
| 异常检查 | 每轴反馈新鲜度≤100 ms、mode=2、无故障、有限数值；反馈速度、偏移和跟踪误差检查 |
| 调度间隔 | 沿用配置 4 ms；工具仅接受 1–10 ms 配置，输出间隔超过 50 ms 锁存故障，恢复执行时冻结目标，不追赶历史轨迹 |
| 方向记录 | 人工填写实际运动轴、正方向观察和说明；不自动改 SDK 配置或生成已标定 MPC 映射 |
| 软件停止 | `stop` 终止本轮点动、冻结最后输出位置并将目标速度设为 0；之后仅可 status/help/quit，不使用 SDK Hold 重设目标 |
| 退出 | 正常退出、信号与异常路径尽可能冻结最后成功提交位置，再调用 SDK Stop；不是失能或急停 |

这些阈值是测试工具的软件门槛，未经过真机调参。SDK 资料中有重力下垂记录，实际机械臂可能无法通过严格到位门；程序会拒绝点动，不自动改增益、改零位或放宽门槛。它不提供重力补偿，也不能据此诊断机械故障。

程序使用普通 Linux 调度，文件/终端输出可能阻塞；50 ms 检查只能在程序恢复运行后处理。SDK 驱动线程独立发送锁存目标，本工具没有独立硬件看门狗，不声称硬实时或故障情况下立即制动。

## 逐轴确认流程

1. 等待“已到位”，默认选中 J1；`status` 查看五轴反馈角／目标角，显示单位为度。
2. 输入 `+`，等待完成与再次到位；观察实际哪个关节运动及方向。
3. 输入 `record 1 same 现场观察说明`。数字指实际运动的物理关节编号；`same`／`opposite` 指与现场采用的模型正方向一致／相反，说明中记录比较视角与参照。不要凭电机数值增减替代肉眼方向确认。
4. 输入 `-` 回到本轮初始目标，再等待到位；输入 `next` 切到下一轴，或 `select 3` 选择指定轴。未返回初始目标不能切轴。
5. 按 J1→J5 逐轴重复；`stop` 终止本轮点动并保持当前目标，之后仅可 status/help/quit；`quit` 退出。中途停止可能停在分数角度，因此不继续累加整数步或重设原点。没有自动五轴真机扫描或自动归零命令。

每次只输入一条命令。程序每拍排空已到达输入，多条非空命令整批拒绝，不积压到未来就绪时执行；quit/stop 优先。超出输入长度上限会结束会话并走停止路径。

程序只允许正向动作后到位时记录方向，拒绝两条已确认命令轴映射到同一物理轴。观察表只是本次人工记录；零位、MPC→SDK 坐标映射和 FK 几何仍未标定。

未来真机使用需要显式 `--backend hardware`，并在交互终端阅读打印的 home、增益和启动行为后输入 `START-HOME`；管道输入、硬件 `--demo` 均提前拒绝。本阶段未运行该入口，也未部署到真机。SDK 路径是构建时链接路径，在控制机运行前仍需准备同版本依赖和配置；不能只复制可执行文件后直接运行。
