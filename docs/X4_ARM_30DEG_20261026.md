# X4 机械臂30°方向测试：当前版本与实测结果

2026-10-26，北京时间。本说明替代之前10°／命令±12°版本；旧记录保留用于对比。

## 当前参数

- 默认单步及循环幅度：**30°**。
- 命令累计行程限制：**±45°**，连续第二次`+30°`欲累计到60°时拒绝。
- 反馈总行程保护：**±45°**，仍相对本轮固定反馈基准，不随换轴重设。
- 默认方向模式：小角度目标残差及其他轴联动偏移仅记录，位置稳定与实际响应方向分别判断。无响应/反向取消自动循环。
- 位置稳定采用原SDK的1秒／1.5°窗；500ms心跳、100ms新鲜度、50ms控制周期、1080°/s反馈速度、实际fault/mode/CAN检查继续生效。
- SDK Start、home、增益、模型不改；没有新增点动轨迹速度上限。`--step-deg 1`或`10`仍可显式选择较小步长，命令累计限制同样为±45°。

## 新内核导致CAN缺失及恢复

重连时真机刚重启到`7.0.0-38-realtime`，两块KCAN USB已枚举，但无CAN接口；系统只有适用于旧`7.0.0-31-realtime`的kcan模块。未尝试强行加载旧模块，也未回退或重启内核。

在开发机`.11`复制真机原有KCAN 1.4.2源码及精确38内核头文件，用隔离GCC15.2和Binutils2.46重建模块。47个源文件与`.config`、`Module.symvers`、`utsrelease.h`的SHA均与真机原件一致；保留完整原编译选项。开发机原GCC13不支持`-fmin-function-alignment=16`，旧assembler不支持`.base64`，因此补齐隔离工具链；没有升级开发机系统工具链。

只把编译后的`kcan.ko`传到真机，安装到当前内核的`/lib/modules/7.0.0-38-realtime/misc/kcan.ko`，depmod后加载。vermagic精确匹配38，srcversion与旧驱动相同；模块SHA256为`9e0d8cf1c33980050c7649a6d246f320bf8e23d98d57d320f10ddcf9f730f7d3`。can0–7恢复后，核对机械臂can4–6物理USB路径仍为`3-9.2:1.0`，仅启用这三个通道。内核再次更新时，需要为新内核提供匹配的编译后模块。

驱动源码、内核头文件、隔离工具链和编译日志全部留在开发Ubuntu的证据目录`kcan38/`，没有新增到Mac或传回真机。

## 操作命令

在开发Ubuntu `.11` 桌面终端运行：

```bash
/home/ubuntu/Zhaohui/sim/.venv/bin/python /home/ubuntu/Zhaohui/sim-x4-interface/tools/x4_arm_compare.py --backend hardware --test-mode direction --step-deg 30
```

认证并准备CAN后，现场准备好再手动输入`START-HOME`。等待稳定，输入关节编号后回车；用`status`确认选中轴，再单独输入`+`、等待稳定、`-`返回原命令目标。回到原命令目标并稳定后，可选下一轴或`loop 1`。GUI数字键选轴，L循环3轮，P完成本次往返后暂停，空格结束本轮动作权限，Q退出。

每条动作单独输入，不排队。当前第二次同向30°会被拒绝，因为60°超过45°命令限制。SDK Stop仍不是失能或硬件急停。
